03 — Methodology

How the data stays current

Three-tier refresh model
1

GitHub Actions — primary

A daily workflow scrapes the PM India registry and commits any new trips to data/visits.json. The page fetches that file first — no runtime scraping in the browser.

2

Live mirror — secondary

If data/visits.json is unreachable (e.g. first load before Actions runs), the page falls back to a live Jina text mirror of the registry and parses it client-side.

3

Embedded snapshot — tertiary

If both network sources fail, the page uses the official snapshot baked into the HTML — the tracker always shows verified data, even fully offline.

Reading the numbers correctly

Every count on this page follows a small set of parsing rules. They're documented here rather than left implicit.

How "Multi-country" is decided

A trip is Multi-country the moment its itinerary lists more than one destination, and Single-country otherwise. A five-day trip touching two countries is one trip with two country touches — not two trips.

Splitting an itinerary into countries

Itinerary labels are split on "&" and "and" to build the per-country list every chart, filter, and KPI reads from. A short allowlist protects official compound names — Trinidad and Tobago, Bosnia and Herzegovina, Antigua and Barbuda, and similar — so they aren't torn into two countries by that same rule.

Each resulting destination is then mapped to one canonical country name, because the registry writes the same country several ways across the years — "USA", "United States of America (USA)", "UAE", "Dubai", "Samarkand". Counts, filters, and the map therefore treat them as one country. The itinerary label itself is always shown exactly as the registry publishes it.

How trip duration is counted

Days is an inclusive count of the registry's stated start and end dates — a trip listed as 12–14 June is 3 days, not 2.

"Reportedly abroad now"

When press coverage describes a trip the official registry hasn't listed yet, it's shown separately and marked Press-reported. It is never counted in any KPI, chart, or export until the registry itself lists it.

"Latest coverage" headlines

Auto-collected third-party news, not fact-checked by this project and not an endorsement of any characterization in a headline. Article dates are cross-checked across multiple search feeds and only ever adjusted earlier, never later, to keep older coverage from being mis-filed as reporting on a new trip.

"Around this visit" outcome indicators

Each trip's drawer and the "Around the visits" chart read data/outcomes.json, refreshed daily by a separate workflow from keyless public sources: the Ministry of External Affairs' "List of Outcomes" documents, UN Comtrade monthly goods trade (India as reporter), OpenAlex counts of papers with an author in each country, the Voeten, Bailey and Strezhnev UN General Assembly voting dataset on Harvard Dataverse, and EXIM Bank's lines-of-credit tables.

These numbers describe what changed around a visit; they never show that a visit caused it. Every flow is shown beside India's overall change over the same fixed window (12 months for trade, three years for co-authorship, three sessions before and two after for UN voting), and a window shortened by a later visit to the same country says so. Rises, falls and no-change results use the same words and the same type. A window that has not yet closed is reported as still open rather than filled with a shorter, noisier one. The design memo behind this, with the sources' licences and the ideas rejected, is in docs/outcome-indicators.md.
