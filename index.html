How data stays current

Three-tier refresh model

1. GitHub Actions (primary)

A daily workflow scrapes the PM India registry and commits any new trips to data/visits.json in the repo. The page fetches that file first — no runtime scraping in the browser.

2. Jina mirror (secondary)

If data/visits.json is unreachable (e.g. first load before Actions runs), the page falls back to a live Jina text mirror of the PM India registry and parses it client-side.

3. Embedded snapshot (tertiary)

If both network sources fail, the page uses the 40-trip official snapshot baked into the HTML. This ensures the dashboard always shows something even fully offline.
