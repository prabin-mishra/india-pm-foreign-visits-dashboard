Keeping it updated

Operational model

1. Trip detection

Each page load attempts to fetch the PM India registry and parse the published foreign-visit rows. If a new trip appears there, it shows up automatically without manually editing the HTML file.

2. Evidence enrichment

For a full production stack, pair each detected trip with a JSON or database record keyed by date and destination. That second layer should store costs, MoUs, implementation events, and citations as they become public.

3. Scheduled upkeep

The most robust setup is a nightly job or GitHub Action that refreshes the dataset, republishes the page, and logs any newly detected trip for review. The page already supports client-side refresh; scheduled publishing adds reliability.
